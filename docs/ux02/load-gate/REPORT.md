## السبب والإصلاح المحدود

استدعاء uxInit موجود داخل callback لـTLB.start في admin.html. ترتيب الموارد: boot.js (عزل تخزين المعاينة) ثم preview-client.js (عينة محلية) ثم talabat-core.js ثم سكربت admin المضمّن ثم adapter.js. الإصدار1 بدأ TLB.start أثناء تحليل الصفحة؛ اكتملت وعود fixture سريعاً قبل تحميل adapter.js الذي يعرّف window.uxInit. الاستثناء التقطته النواة عبر bootFail فأبقت طبقة Could not load the app. السبب ترتيب التهيئة، وليس دليلاً على اختلاف إصدارات الموارد.

الإصلاح المحفوظ سابقاً يؤخر TLB.start إلى DOMContentLoaded. كشف اختبار المتصفح بعده خطأً ثانياً: sync في adapter يحاول before على عنصر غير موجود قبل أول render. أضيف حارس يمنع مزامنة إطار فارغ؛ MutationObserver القائم يستأنف بعد ظهور المحتوى. لم تُعدّل النواة أو boot.js أو CSS أو مكونات الملاحة أو الحسابات أو الصلاحيات. الفرق التطبيقي عن الإصدار1 محصور في انتظار DOMContentLoaded وحارس أول عنصر في app؛ صفحة ux02-review.html السابقة أداة QA مستقلة وليست تغييراً للشكل.

اختبار tests/ux02-loading.cjs أعاد إنتاج فشل الإصدار1 وفشل المحوّل قبل الحارس ثم نجح بعده.
